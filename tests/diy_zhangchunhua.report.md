## 已修复缺陷

文件：`character/diy/skill.js`
位置：约 8584 和 8607 行

问题：`diy_geiyuan.content` 引用了未定义变量 `litAny`，任何会执行至完成判断的弃牌事件均可能报错。

修复：事件开始前记录 `litBefore = info.lit.length`，在完成判断中检查 `info.lit.length === litBefore`，避免虚构变量并保留重复触发防重逻辑。

## Google Chrome 真正对局验证（2026-10-25）

通过本机 Deno 服务器（8089）和独立 Chrome 155（CDP 9252），实际执行选将并进入无尽 3-1（1v3）战局；从浏览器通过 ES Module 读取真实游戏引擎状态。

- 无尽模式初始菜单可以打开；主将选择 diy_zhangchunhua；其余两个位置由测试脚本选择合法候选武将。
- 进入真实对局，主将 8/8 体力，引擎注册了 19 个技能。
- 〖割圆〗真实界面显示 13 点数和 0/13 进度，`game.me.storage.diy_geiyuan.order.length===13`。
- 进入张春华出牌阶段，确实展示〖天启〗、〖杀意〗、〖镇魂〗、〖国色〗控件。
- 实际点击〖镇魂〗 -> `chooseToDiscard` 事件 -> 选手牌 2 点闪并弃置：手牌从 6 张减少到 5 张；三名敌人 `hasSkill('diy_zhenhun_fengyin')===true`；〖割圆〗真实存储 `lit=[2]`；本轮无 JS 异常。
- 初期 CDP 空白/卡顿源于初始化 GPLv3 确认弹窗；在浏览器脚本执行前连接 CDP 并处理弹窗后正常加载。无用户手势的 JS 合成点击曾触发 `NotAllowedError: HTMLMediaElement.play()` 以及游戏错误弹窗；专用测试 Chrome 加入 `--autoplay-policy=no-user-gesture-required` 后实测无此异常。此参数只为测试自动化，不应当作游戏生产配置。
- 某些随机武将图片请求返回 404（与张春华技能执行无直接关系）。

复测脚本保存在 `tests/diy_zhangchunhua.chrome.smoke.mjs`。运行时需要先启动 Deno 项目服务器和隔离的 Chrome `--remote-debugging-port=9252`，避免使用本人日常 Chrome 资料目录。测试脚本在隔离浏览器中自动创建新游戏，可能清除该测试浏览器中的旧无尽存档。
